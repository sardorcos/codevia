# Codevia Pocket — Compact UI 0.3

**Status:** самостоятельная работающая дизайн-сборка (UI release candidate), а НЕ обновление опубликованного Codevia Pocket 0.2. Исходный репозиторий Site-проекта в текущей рабочей среде недоступен. Существующий сервис и его пользовательские проекты **не менялись**.

## Что изменено визуально

- Главная упрощена: компактная шапка, три быстрых действия, последний проект, один список.
- Рабочая зона стала приоритетом: без больших hero-блоков и повторения вкладок.
- Два варианта плотности: компактный и комфортный.
- Общие кнопки: основные, вторичные, бесцветные, опасные. Размер кнопок и отступы одинаковы на всех экранах.
- Код: узкая панель вкладок, номера строк, подсветка, панель специальных клавиш, переключатель переноса, копирование.
- Предпросмотр: почти всю доступную высоту занимает страница, минимум кнопок вокруг.
- Серверы: компактные профили; никогда не показывается выдуманное «подключено».
- Везде есть безопасные области iOS, динамический размер шрифта кода и минимальные области нажатия.

## Какие действия действительно работают

- Создание проектов из HTML/CSS/JS, Python, PHP или пустого шаблона.
- Создание и редактирование текстовых файлов.
- Автосохранение в IndexedDB по мере изменения текста, если хранилище доступно.
- Поиск файлов, группировка по типу и история контрольных точек.
- Локальный HTML-предпросмотр со связанными CSS/JS из проекта в sandboxed iframe.
- Проверка JSON и ссылок на локальные файлы HTML/CSS.
- Импорт ZIP (STORE и Deflate, если браузер поддерживает DecompressionStream('deflate-raw')) с ограничениями размера, CRC32 и блокировкой обхода путей.
- Экспорт ZIP с сохранением имён и структуры (метод STORE).
- Сохранение профилей серверов **без** учётных данных и приватных ключей.
- Смена плотности UI, размера шрифта, ручная точка восстановления.

## Что сюда не перенесено

**Python/PHP runtime, SFTP/FTP/SSH, реальный деплой и серверный Bridge отсутствуют в этом автономном HTML-превью.** Они остаются в основной Codevia Pocket 0.2. Чтобы перенести новый интерфейс без регресса, используйте `docs/INTEGRATION.md`; экран запуска/серверов в превью явно сообщает об отсутствии подключённой среды, а не рисует ложный успешный результат.

## Локальный запуск

Не нужен Node.js и установка пакетов. Из каталога проекта:

```bash
python3 -m http.server 8765
```

Открыть `http://localhost:8765/`. Все файлы пользовательского проекта обрабатываются локально, сервер `http.server` нужен лишь для раздачи статических ресурсов UI. Адрес из данного примера не опубликован в интернете.

На телефоне откройте этот сервер через адрес компьютера в вашей локальной сети либо разверните статический UI в своей инфраструктуре. Для демонстрации без сервера доступен `codevia-ui-0.3-standalone.html`, но сохранение через IndexedDB при открытии `file://` зависит от браузера.

## Проверки

```bash
python tests/test_ui.py
```

Тест использует браузер Chromium и подставляет только тестовый in-memory IndexedDB, потому что автоматизированный браузер в среде сборки не допускает локальные URL. Это проверка UI-потока, а не тест реального сохранения на iOS или работы серверного Bridge.

## Безопасность

- JavaScript из импортируемого HTML выполняется в iframe с `sandbox="allow-scripts"`, без `allow-same-origin`.
- Политика CSP ограничивает сетевые запросы, формы, внешние скрипты и источники в предпросмотре.
- ZIP-импорт не допускает пути `../` или абсолютные пути, проверяет CRC и ограничивает размеры.
- Проект и настройки сохраняются только в хранилище устройства. Для резервной копии пользователь экспортирует ZIP.
- Форма FTP/SSH ничего не подключает в этом демо и не запрашивает пароли.

## Совместимость

Интерфейс адаптирован под 375–430 px (iPhone), планшеты и десктоп. Реальные проверки на iOS/Safari и сборка Xcode для этой дизайн-ветки ещё не проводились.
