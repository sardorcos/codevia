## Главное

1. **Приложение только на русском, а карточка в App Store основная английская.** Американский пользователь прочитает английское описание, скачает приложение и увидит русский интерфейс. Отсюда плохие отзывы и риск замечания по Guideline 2.3 (метаданные не соответствуют приложению). На «английских» скриншотах тоже русский интерфейс. Это мой промах (С).
2. **Я отправил приложение на ревью без проверки на настоящем iPhone.** В аудите 2 я сам записал, что сначала нужен внутренний TestFlight по `docs/QA_CHECKLIST.md`. Сборка 10 в TestFlight есть, но прогона чек-листа не было. Ревьюер подтверждает, что четыре его находки (Р6, Р9, Р10, Р11) проявляются только на устройстве: это падения WebView от нехватки памяти (С).
3. **Есть сценарии потери данных и неработающего восстановления** (Р1, Р2, Р4, Р5). Их нужно закрыть в 1.0.1 до того, как появятся первые пользователи.

## (Р) Код: подтверждённые дефекты

| # | Серьёзность | Дефект | Исправление |
|---|---|---|---|
| Р1 | высокая | Резервная копия разрешена до 150 МБ, а импорт отклоняет любой ZIP больше 60 МБ (`app.ts:482`). Копию, которую приложение само сделало, нельзя восстановить | Поднять порог импорта до лимита резервной копии с запасом на заголовки |
| Р2 | высокая | Дедупликация версий только по хешу. На iOS blob хранится как `hash.t` или `hash.b`, а читается с нужным суффиксом. Пустой `.gitkeep` (бинарный) и пустой `__init__.py` (текст) дают один хеш. Восстановление падает с ошибкой «Повреждена версия», в вебе меняется тип файла | Тип файла сделать частью ключа, а при чтении пробовать другой суффикс |
| Р3 | высокая | Python выполняет **старую** версию модулей пользователя. Каждый запуск идёт в новую папку `run{N}`, а кэш модулей чистится только для текущей. Сценарий: правишь `utils.py`, нажимаешь «Запустить», работает старый код | Одна постоянная рабочая папка, очистка `sys.modules` для всех пользовательских модулей |
| Р4 | высокая | Файлы и папки с `#`, `?` или именами вроде `constructor`, пришедшие через «Файлы», ломают экспорт ZIP и **всю** резервную копию (`zipFiles` → `normalizePath` бросает исключение) | Чистить имена при чтении с диска и при «усыновлении» папок либо не бросать исключение в `zipFiles` |
| Р5 | средне-высокая | Каждое удаление файла создаёт автоверсию, а хранится только 10 последних. Удалил 11 файлов — первый потерян навсегда, хотя уведомление обещает возможность восстановить. Так же вытесняются версии «Перед восстановлением» | Не удалять версии моложе 24 часов; групповое удаление и удаление папки как одна версия |
| Р6 | средняя | Папки запусков Python никогда не удаляются: память воркера растёт с каждым запуском (8 МБ CSV × 30 запусков ≈ 240 МБ) | То же исправление, что в Р3 |
| Р7 | средняя | Сборка мусора читает все версии всех проектов почти при каждом сохранении версии, внутри очереди записи | Индекс ссылок на blob-ы, сборка мусора в простое |
| Р8 | средняя | Каждое автосохранение перекодирует весь проект ради размера; каждое нажатие клавиши копирует весь документ | Размеры считать инкрементально, текст читать только по таймеру сохранения |
| Р9 | средняя | Быстрый вывод (`print` в цикле) — это одно сообщение на каждую запись, и каждое вызывает перерисовку. UI зависает, «Стоп» не реагирует | Буферизация в воркере (50 мс / 4 КБ), вставка в DOM раз в кадр |
| Р10 | средняя | Предпросмотр заново кодирует картинку в base64 при каждом упоминании и встраивает все файлы до 12 МБ. Галерея превращается в страницу на 40–50 МБ при каждой правке | Кэш data-URL или передача ArrayBuffer и `blob:`-ссылки внутри iframe |
| Р11 | средняя | «Поделиться» для большого экспорта строит base64-строку целиком: на 150 МБ уходит больше 500 МБ памяти | Писать файл порциями (`appendFile`) |
| Р12 | средняя | В предпросмотре перехватывается только `fetch`, а `XMLHttpRequest` нет: `$.getJSON` и `axios` не работают | Минимальная подмена XHR поверх файлов проекта |
| Р13 | средняя | `location.href = 'about.html'` ведёт в пустоту, а формы `method=get` в PHP-уроках не работают | GET-формы превращать в `navigate` с параметрами, позже добавить `$_POST` для PHP |
| Р14 | низкая | Поиск в «Файлах» на каждое нажатие перекодирует все файлы ради размеров | Кэш размеров, debounce 150 мс |

## Идеи для улучшений (кроме исправлений)

**Для новичков, нашей главной аудитории**
- «Опубликовать сайт» в GitHub Pages одним нажатием (см. `GITHUB.md`).
- Встроенные мини-курсы из 10–15 шагов: HTML → CSS → JS, Python-основы, PHP-формы. В каждом шаге проверка результата (запуск плюс сравнение вывода).
- Понятные ошибки: перевод типичных трассировок Python и PHP на человеческий язык с указанием строки. Подсветка строки в редакторе уже есть, нужен текст подсказки.
- Шаблоны: лендинг, портфолио, Telegram-подобная вёрстка, калькулятор на Python, гостевая книга на PHP.

**Для ежедневной работы**
- Разделённый экран «код + предпросмотр» на больших iPhone в горизонтальной ориентации и на iPad, с живым обновлением.
- Панель символов над клавиатурой, настраиваемая под язык: `<>{}()[];:=$` и Tab.
- Быстрое открытие файла (Cmd+P / жест), переход к определению внутри проекта.
- Emmet для HTML/CSS.
- Интерактивный `input()` через SharedArrayBuffer. Нужны заголовки COOP/COEP в нативной схеме: проверить, что WKWebView это поддерживает.
- Пакеты Python (numpy, pandas) как необязательная офлайн-загрузка из бандла Pyodide.
- Ярлыки «Команд» и виджет «последний проект».

**Качество**
- Выполнить пункт С2 и добавить в CI тесты на память и производительность (большой проект, быстрый вывод, 30 запусков).
- Свести общие типы и константы в один модуль. Добавить проверку, что каждый лимит экспорта и резервной копии не превышает лимит импорта (это ловит класс ошибок Р1).
