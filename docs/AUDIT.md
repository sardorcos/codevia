# Аудит Codevia Pocket UI 0.3 — путь к продакшену и App Store

Дата: 21.11.2026 · Объект: `Codevia_Pocket_UI_0.3_Source.zip` (index.html, src/app.js, src/styles.css, tests/, docs/)

## 1. Вердикт

Сборка 0.3 — аккуратный **дизайн-прототип**, но не продукт. Безопасность в базе продумана хорошо: экранирование HTML, sandbox-iframe без `allow-same-origin`, CSP в предпросмотре, защита ZIP от `../`, пароли не хранятся. Но в App Store в таком виде её не пропустят, а у пользователей она сломается.

Главные причины:

1. **Половина функций — заглушки.** Python/PHP «требуют движок», серверы «требуют Bridge», в интерфейсе висят «UI 0.3» и «LOCAL UI PREVIEW». Ревьюер Apple отклонит это по Guideline 2.1 (неполное приложение) и 2.2 (демо/бета-версии не допускаются).
2. **Нет нативной оболочки.** Нет проекта Capacitor/Xcode, иконок, launch screen, privacy manifest. Экспорт через `<a download>` в WKWebView не работает.
3. **Кодовая база нежизнеспособна для поддержки.** Около 60 КБ JS записаны в строки по 1,5–2,8 тыс. символов. Состояние глобальное, рендер — полный `innerHTML` на каждое действие. `codevia-ui-0.3-standalone.html` — вторая копия того же кода, синхронизируемая вручную.

**Рекомендация.** Не публиковать 0.3 как отдельное приложение, а сделать то, что уже написано в `docs/CODEX_TASK.md`: перенести дизайн-систему в существующий React + TypeScript + Capacitor проект 0.2, где есть CodeMirror, Pyodide, PHP.wasm и Bridge. Ниже — что исправить в любом случае: часть багов (предпросмотр, ZIP, хранилище) почти наверняка есть и в 0.2, если логику переносить отсюда.

## 4. Подтверждённые баги

### Критические / высокие

1. ✅ **Ловушка полноэкранного предпросмотра.** Кнопка «Открыть на весь экран» (`open-preview-tab`) растягивает `.preview-shell` на `position:fixed; inset:0; z-index:100`. Тулбар с кнопкой выхода и нижняя навигация оказываются **под** iframe (`elementFromPoint` в обеих точках возвращает `IFRAME`). Escape не обрабатывается. На телефоне выйти можно только перезапуском.
   *Исправление:* кнопка «Закрыть» внутри полноэкранного слоя, обработчик Escape, безопасные отступы.
2. ✅ **`</script>` в JS пользователя ломает предпросмотр.** В `makePreviewDoc` сначала экранируется `</script` → `<\/script`, а следующая строка (`html.replace(/<script>[\s\S]*?<\\\/script>/g, …)`) возвращает первое вхождение обратно. Пример: `const s = "</script>"` — скрипт не выполняется, хвост кода выводится текстом на страницу.
   *Исправление:* удалить эту строку. Надёжнее вообще не инлайнить, а отдавать файлы через виртуальный сервер (см. §6.3).
3. ✅ **Предпросмотр не понимает реальные проекты.**
   - Пути `../styles.css`, `./x.css`, `/x.css` не резолвятся (`directory + rel`). Проверено: `pages/about.html` → `../styles.css` не подключается.
   - Картинки и шрифты из проекта не показываются: CSP `img-src data: blob:`, и они не инлайнятся.
   - Ссылки на другие страницы (`<a href="about.html">`) уводят iframe в пустоту.
   - `<script type="module">` с `import` не работает.
   - `<link rel="manifest" href="manifest.json">` заменяется на `<style>{json}</style>` (регэксп ловит любой `<link href>`).
   - Внешние CDN (Bootstrap, Google Fonts) молча блокируются, без объяснения.
4. **Тихая потеря данных при переполнении хранилища.** `writeStore` слушает только `oncomplete`/`onerror`. При `QuotaExceededError` транзакция завершается событием `abort`, промис не разрешается никогда: индикатор навсегда «Сохранение…», ошибки нет, данные не записаны.
   *Исправление:* `tx.onabort = () => reject(tx.error)`, понятное сообщение и предложение экспортировать ZIP.
5. **Хранилище недоступно — пользователь об этом не знает.** Если `indexedDB.open` падает (приватный режим, `file://`, политика), показываются демо-проекты как обычно. Каждое сохранение падает (`db` undefined) и выдаёт одинаковый тост, а правки теряются при закрытии.
   *Исправление:* постоянный баннер «Изменения не сохраняются», блок деструктивных действий, предложение экспорта.
6. **Каждое нажатие клавиши пишет в IndexedDB ВСЁ состояние**: все проекты со всеми снимками истории (до 25 проектов × 12 снимков × до 50 МБ). На реальных объёмах — фризы ввода, расход батареи, риск квоты.
   *Исправление:* хранить запись на файл/проект (`projects`, `files`, `snapshots` — отдельные object store), писать только изменённый файл.
7. ✅ **ZIP-бомба.** Лимит размера проверяется по значению *из заголовка*, а реальная распаковка `DecompressionStream` буферизуется целиком до проверки. Архив на 49 КБ с заявленным размером 100 байт распаковался в 50 МБ и только потом отклонён по CRC. При лимите 25 МБ на ZIP и сжатии ~1000:1 приложение можно уронить по памяти.
   *Исправление:* читать поток чанками, считать байты, обрывать при превышении `plain` или общего лимита.
8. ✅ **Редактор: Undo/Redo не работают для вставок.** `setRangeText` не попадает в стек отмены (проверено: после «{ }» → «Отменить» текст не вернулся). Используется устаревший `document.execCommand`. Стек отмены теряется при каждом `render()` (смена вкладки, перенос строк), потому что textarea создаётся заново.
   *Исправление:* CodeMirror 6, как в 0.2.

### Средние

9. ✅ **Цели нажатия меньше 44 pt в режиме по умолчанию.** «Компактный» режим — дефолт и ставит `--tap: 40px`. Измерено: «Настройки» 40×40, «Продолжить» высотой 30, «Новый/Импорт/Серверы» 43, клавиши keybar 34. Apple HIG требует 44×44 pt.
10. ✅ **iOS зумит страницу при фокусе в поле.** Поля ввода 14px, редактор 13px; Safari/WKWebView увеличивает всё, что меньше 16px. Нужно `font-size: 16px` для `input/textarea`, а масштаб редактора делать через `transform`/CodeMirror, а не размером шрифта textarea.
11. ✅ **Нет `safe-area-inset-top`.** `.topbar` имеет `padding-top: 0` при `viewport-fit=cover`. В Capacitor и в режиме PWA шапка уйдёт под Dynamic Island/чёлку. Также нет `inset-left/right` для альбомной ориентации.
12. ✅ **Иконка веб-проекта пустая.** В `renderHome` строка `"</>"` вставляется в HTML без экранирования. Парсер видит пустой закрывающий тег и выбрасывает его. На `home.png` у «Studio portfolio» пустой коричневый квадрат.
13. ✅ **Кнопка «{ }» ставит курсор после `}`** (caret = 2 вместо 1). То же для `[ ]`, `< >`. Курсор должен оказаться внутри скобок.
14. ✅ **ZIP: мусор и кодировки.**
    - Импортируются `__MACOSX/._*` и `.DS_Store` (архивы с Mac) — их нужно фильтровать.
    - Имена на кириллице из Windows-архивов без UTF-8-флага (CP866) превращаются в `�ਢ��.txt`. Для русскоязычной аудитории это частый случай: нужен фолбэк на CP866, если бит 11 не установлен.
    - Дубликаты имён и коллизии регистра молча перезаписываются.
15. **Номера строк врут в режиме переноса.** Гуттер показывает логические строки, а перенесённая строка занимает несколько визуальных.
16. **Подсветка и гуттер перестраиваются целиком на каждое нажатие** (регэкспы по всему файлу). На файлах от ~200 КБ ввод заметно лагает. Решается CodeMirror.
17. **История версий.** Лимит 12 снимков, автоснимки («Перед удалением файла», «Перед восстановлением») вытесняют ручные. Каждый снимок — полная копия, включая бинарные файлы.
    *Исправление:* отдельные лимиты для авто- и ручных снимков, хранение по хэшу содержимого (дедупликация).
18. **Кнопка «⋯» у сервера сразу удаляет профиль** (через `confirm`). Иконка обещает меню, а делает деструктивное действие.
19. **Несогласованные лимиты импорта.** Лимит 25 проектов проверяется при создании, но не при импорте. При импорте нескольких файлов нет общего лимита размера; одинаковые имена перезаписываются.
20. **Форма сервера.** Регэксп хоста отвергает IPv6 и допускает `-.-`. `required` на поле «Название» делает мёртвым фолбэк `name || host`. Для FTPS implicit порт по умолчанию 990, а не 21.
21. **Полный `innerHTML`-рендер** сбрасывает скролл, фокус и текст поиска при любом действии. `renderEditor` мутирует состояние во время рендера.
22. **Фиктивные элементы интерфейса.** «Тёмная тема — Включена» не переключается. Миниатюра в «Продолжить работу» показывает захардкоженный текст «Идеи становятся продуктами.», а не проект. Поиск файлов ищет по `textContent`, поэтому запрос «кб» совпадает со всеми строками.

### Доступность (VoiceOver / WCAG)

23. Строки проектов и файлов — `div` с `data-action`: не фокусируются с клавиатуры, VoiceOver не объявляет их кнопками. Нужны `<button>` или `role="button" tabindex="0"` с обработкой Enter/Space.
24. Модальные листы (`role="dialog"`): нет переноса фокуса внутрь, нет focus trap, фокус не возвращается на исходную кнопку.
25. Контраст ниже 4.5:1 для мелкого текста: `--weak #687281` — 3.97:1, плейсхолдеры `#6d7582` — 4.15:1, номера строк — 4.2:1. Шрифты 9–10.5px в бейджах и подписях — слишком мелко.
26. Нет поддержки Dynamic Type (README это утверждает, но реализован только ползунок в настройках). В WKWebView можно опираться на `font: -apple-system-body` и масштабировать токены.

### Сборка, тесты, инфраструктура

27. Нет системы сборки, линтера, TypeScript и `package.json`. Код минифицирован вручную; `standalone.html` — ручная копия, которая уже отличается от `src/app.js` (экранирование `<\x73cript`).
28. Тесты захардкожены на `/usr/bin/chromium` и запускаются **только в Chromium**, хотя целевая платформа — WebKit (iOS). IndexedDB подменён моком, поэтому реальное сохранение не тестируется. Тесты пишут скриншоты в корень репозитория. `test-results.txt` — устаревший артефакт. CI нет.
29. `manifest.webmanifest`: нет иконок, `theme_color` не совпадает с `<meta theme-color>`, нет service worker — заявленная работа офлайн не обеспечена.
30. Нет мониторинга ошибок и версионирования схемы данных: IndexedDB v1 без миграций, форма `state` не версионирована. Любое изменение формата в 0.4 рискует сломать данные пользователей.

## 6. План доведения до продакшена

### Этап 0 — решение по архитектуре (1–2 дня)
- Подтвердить: 0.3 — это **дизайн для 0.2**, а не отдельный продукт. Работать в репозитории 0.2, ветка `feature/compact-ui-0.3`.
- Стек: Vite + React + TypeScript (strict) + ESLint/Prettier, Capacitor 6/7 для iOS.

### Этап 1 — исправить ядро (1–2 недели)
1. **Редактор:** CodeMirror 6 — undo/redo, большие файлы, автоотступы, автопарные скобки, поиск и замена, корректный перенос строк.
2. **Хранилище:** нативная файловая система (Capacitor Filesystem) или SQLite вместо IndexedDB в WKWebView: iOS может вычистить данные WebView при нехватке места. Схема с версией и миграциями, запись только изменённого файла, обработка `abort`/квоты, `navigator.storage.persist()` в вебе.
3. **Предпросмотр как виртуальный сервер:** на iOS — свой URL-scheme handler (`WKURLSchemeHandler` / Capacitor `server.iosScheme`), в вебе — Service Worker. Это одним махом решает пути `../`, картинки, шрифты, `fetch('data.json')`, ES-модули, многостраничные сайты и проблему `</script>`. Добавить переключатель «Разрешить сеть» для CDN.
4. **ZIP:** потоковая распаковка с подсчётом байтов, фильтр `__MACOSX`/`.DS_Store`, фолбэк CP866, обработка коллизий («Заменить / Переименовать / Пропустить»), экспорт с Deflate (`CompressionStream`).
5. **Экспорт и шаринг:** Filesystem + Share вместо `<a download>`.

### Этап 2 — функции, без которых нельзя в стор (2–4 недели)
1. **Python:** Pyodide в Web Worker, упакованный в бандл; кнопка «Стоп» (terminate worker), таймаут, вывод stdout/stderr, понятные ошибки.
2. **PHP:** PHP.wasm в воркере, отрисовка результата в предпросмотре.
3. **Серверы:** предпочтительно SSH/SFTP **на устройстве** (нативный плагин на Swift NIO SSH / Citadel или libssh2). Тогда пароли не уходят третьей стороне, а privacy-лейблы проще. Keychain для секретов, пиннинг host key, явный diff перед публикацией, блок при внешнем изменении файла, откат.
4. Если что-то из этого не готово к релизу — **убрать с экрана**, а не показывать заглушку.

### Этап 3 — iOS-полировка (1–2 недели)
- Safe areas (top, left, right), шрифт полей 16px, цели нажатия ≥44 pt во всех режимах плотности.
- Keybar как accessory над клавиатурой: `visualViewport` / Capacitor Keyboard plugin, `pointerdown.preventDefault`, чтобы клавиатура не мигала.
- Нативные action sheets вместо `confirm()`; haptics; кнопка выхода из полноэкранного режима.
- VoiceOver: кнопки вместо `div`, фокус в модалках, контраст ≥4.5:1, Dynamic Type.
- Интеграция с «Файлами» и «Открыть в Codevia» для `.zip`.

### Этап 4 — качество и выпуск (1–2 недели)
- Unit-тесты (Vitest): `normalizePath`, ZIP (бомбы, кодировки, коллизии), `scanProject`, миграции хранилища.
- E2E (Playwright) в **WebKit** и Chromium, на реальном IndexedDB или Filesystem. Скриншот-ревью 375/390/430 и iPad.
- CI (GitHub Actions): lint, typecheck, тесты, сборка; Xcode Cloud или fastlane для TestFlight.
- Мониторинг крэшей (например, Sentry) — без отправки содержимого файлов пользователя, с упоминанием в политике приватности.
- TestFlight: минимум 1–2 недели внешнего бета-теста на разных iPhone, включая старые модели (iOS 16) и маленький экран (SE 375 pt).
- App Store Connect: описание (ru + en), ключевые слова, скриншоты, privacy policy, privacy labels, export compliance, возрастной рейтинг, контакт поддержки.

## 7. Быстрые правки (можно сделать за день прямо в 0.3)

1. Удалить строку «раскрытия» `<\/script>` в `makePreviewDoc`.
2. Кнопка закрытия и Escape для полноэкранного предпросмотра.
3. `tx.onabort` в `writeStore`; баннер при недоступном хранилище.
4. `--tap: 44px` во всех режимах; `font-size: 16px` у `input` и `textarea`.
5. `padding-top: env(safe-area-inset-top)` у `.topbar`; `inset-left/right` у основных контейнеров.
6. Экранировать `"</>"` → `esc("</>")`.
