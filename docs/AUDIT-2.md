# Аудит 2: самопроверка перед TestFlight

Дата: 21.11.2026 · Объект: Codevia Pocket 1.0.0 после переработки (коммиты `0f7d609` → `82fdb9b`)

Два независимых взгляда:
- **(С)** — моя самокритика на уровне продукта и релиза;
- **(Р)** — независимый ревьюер. Он получил только код, без моих выводов, и работал в режиме «только чтение».

Каждую находку я проверил по коду, прежде чем исправлять.

## Итог

Найдено 30 проблем. Исправлено 26, они покрыты тестами (unit 64, E2E 20). 4 осознанно отложены, причины ниже. Главный риск — **приложение ещё не запускалось на реальном iPhone** (среда сборки — Linux). Поэтому первая сборка идёт во внутреннее тестирование TestFlight по `docs/QA_CHECKLIST.md`, а не сразу на ревью App Store.

## Исправлено

### Потеря и порча данных
| # | Находка | Источник | Исправление |
|---|---|---|---|
| 1 | Новый проект мог занять папку, уже существующую в «Файлах», и при удалении стереть файлы пользователя | Р | Имя папки сверяется с реальным содержимым Documents. Папки без метаданных автоматически становятся проектами |
| 2 | Если сохранение не удалось, при смене проекта или выходе правки терялись молча | Р | `ensureSaved()` блокирует уход. Пользователь выбирает: повторить, экспортировать ZIP из памяти, выйти без сохранения или остаться (E2E-тест) |
| 3 | Файлы в Windows-1251, UTF-16 и бинарные файлы без расширения портились при импорте; на iOS такие файлы пропадали из проекта | Р | Строгое декодирование UTF-8. Остальное хранится байт-в-байт, в меню файла есть явное «Преобразовать в UTF-8» (тесты) |
| 4 | Очистка истории могла удалить данные, которые одновременно переиспользует новая версия | Р | Все записи в хранилище идут через одну очередь (тест на гонку) |
| 5 | Восстановление сначала удаляло старые файлы, потом писало новые: при сбое данные терялись | Р | Сначала запись, потом удаление (тест на порядок операций) |
| 6 | Ошибка чтения папки воспринималась как «папка пуста», после чего следовало рекурсивное удаление | Р | `listOrNull` + нерекурсивный `rmdir` только для подтверждённо пустой папки |
| 7 | При ошибке переименования метаданные и папка расходились | Р | Откат перемещения папки |
| 8 | Удалённый проект мог «воскреснуть» из-за незавершённого сохранения | Р | Удаление ждёт текущее сохранение и встаёт в очередь после него |
| 9 | Веб- и нативная реализации Filesystem по-разному возвращают данные | С | Всё пишется и читается как байты (base64) одинаково на обеих платформах |
| 10 | Полную резервную копию больше лимита одного проекта нельзя было восстановить; при нехватке места восстановление обрывалось на середине | Р | Отдельные лимиты для архива, проверка размера перед созданием копии, проверка свободных мест под проекты до начала восстановления |

## Осознанно отложено

| Что | Почему | Когда |
|---|---|---|
| Проверка на реальном iPhone и в WebKit | В среде сборки нет macOS и Xcode. CI гоняет WebKit, ручная проверка — по `docs/QA_CHECKLIST.md` во внутреннем TestFlight | До внешнего бета-теста |
| Полная перерисовка экрана на действия (а не точечные обновления) | Смягчено: фокус, скролл и позиция в редакторе сохраняются. Перевод на компоненты — большой рефакторинг без пользы для 1.0 | 1.1 |
| Интерактивный `input()` (сейчас ввод задаётся заранее) | Нужен SharedArrayBuffer, а значит COOP/COEP-заголовки в нативной схеме Capacitor | 1.1 |
| Правки файлов в «Файлах», пока проект открыт в приложении | Изменения подхватываются при следующем открытии проекта; одновременное редактирование в двух местах перезапишет одно другим | 1.1 (слежение за mtime) |
| Серверы (SFTP/FTP), английский интерфейс, iPad, пакеты Python (numpy) | Вне объёма 1.0. Экран серверов без реального подключения App Store отклонил бы по 2.1 | Дорожная карта |
